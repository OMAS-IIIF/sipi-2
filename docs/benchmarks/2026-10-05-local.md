# Local worker benchmark — 2026-10-05

## Setup

Apple M5 Max, 18 logical CPUs, 36 GiB RAM; macOS 27.0.1 arm64. SIPI and Conan
dependencies built in Release with Apple Clang 21 / C++20; Python 3.13.9 load
runner. No simultaneous builds or sanitizer runs during timing. Ordinary desktop
applications remained open, so this is not an isolated laboratory benchmark.

Two deterministic 4096 x 4096 RGB8 masters: pyramidal tiled LZW TIFF (256px tiles)
and lossless JP2 (1024px tiles, six resolutions). Eight loopback HTTP clients,
persistent connections, two adjacent 8x8 tile grids (1:1 and 1:2), output 256x256
JPEG. Five repetitions with shuffled 1/2/4-worker order. Metadata warmed first;
OS file caches not flushed. No Lua policy, Caddy/TLS or S3 in the timed path.

Cold = 128 unique requests into an empty **encoded-result cache**, including
synchronous cache publication. Warm = 16,384 requests for those same cached tiles.
Every response was checked against the same source/URL's one-worker uncached
reference, including baseline JPEG dimensions. All **495,360 measured responses**
matched, without HTTP errors; every trial retained exactly 128 cache entries.

The initial exploratory run used only 1,024 warm requests. Its warm phases were
too brief for useful sampling, so the final run below lengthened them. No values
from that preliminary run are mixed into this table.

## Interpretation

- Four workers deliver **2.29x TIFF throughput** and **3.85x JP2 throughput** on
  cold result-cache requests. Cold p95 falls from approximately 15.7 to 7.5 ms
  for TIFF and 457 to 120 ms for JP2 under eight-client concurrency.
- The TIFF path scales less than linearly. Its measured path includes serialized
  cache index/file publication and fsync as well as decode/encode; this measurement
  alone does not identify their individual contributions. Do not call it a pure
  codec benchmark or infer a specific bottleneck without profiling/control runs.
- Warm cache throughput is roughly 15,000 req/s, with substantial spread in some
  runs. More image workers show no reliable benefit here. Client hashing/Python,
  loopback HTTP and serialized cache bookkeeping may limit the observed rate;
  these data do not establish the server's maximum cached-response capacity.
- Sampled RSS remained modest for these small output tiles: approximately
  15–17 MiB for TIFF and 21–37 MiB for JP2 as workers increased from one to four.
  Warm phases retain native allocator memory from preceding cold work. These
  values do not predict full-image export, larger crops or simultaneous slow
  clients, and do not replace memory-budget planning. Cold TIFF phases have only
  a few RSS samples; brief peaks can be missed.
- This supports retaining the conservative default cap of **four workers** for
  now. It does not justify increasing the cap or choosing a repository format
  purely from these synthetic results. Real archival JP2 parameters and image
  content can behave differently; TIFF/J2K tile dimensions differ in this fixture.

## ThreadSanitizer follow-up

Rebuilt pinned Drogon 1.9.13 and Trantor 1.5.28 with `-fsanitize=thread`, together
with SIPI, using `benchmarks/build_http_tsan.py`. The separate Conan generation
points at those instrumented archives; regular Debug/Release packages are intact.

The parallel HTTP test passed **four runs** without a TSan report, and the direct
worker/render/cache test passed too. No suppressions or `TSAN_OPTIONS` overrides
were used. Earlier callback/lock-free queue reports disappeared when these
libraries were instrumented, supporting invisible synchronization as their cause.
Other native dependencies remain uninstrumented; clean exercised paths are not a
proof of all interleavings or all library internals. The sanitized binary was not
used for performance measurements.

## Regression checks

All 34 Release suites passed: 32 regular suites plus both local MinIO integration
suites (run separately after enabling `SIPI_TEST_S3`). No project compiler warnings
were emitted by the Release build. Performance measurements finished before these
additional builds/tests began.
