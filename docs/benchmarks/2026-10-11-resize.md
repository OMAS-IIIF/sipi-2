# Resampling baseline — 2026-10-11

## Scope and reproducibility

Unmodified SIPI production kernels, native Apple M5 Max / ARM64, macOS 27.0.1,
Apple LLVM 21.0.0, Release `-O3 -DNDEBUG`. One benchmark thread; Grok uses one
codec worker. No new SIMD implementation, fast-math or native-CPU build flags.
These are local baseline measurements, not Intel/AMD results or an HTTP capacity
benchmark. They must not be compared directly with the earlier Linux Docker runs.

Two runs, reversed real-file order; two unmeasured warmups and nine measured
iterations per case per run. 15 synthetic cases (gray/RGB/RGBA) and 36 render-core
cases (six existing archive images × TIFF/JP2 × three requests). 918 measured
results in total. All repeated pixel fingerprints and JPEG fingerprints are stable
within and across runs. Fingerprints check repeatability, not equivalence between
formats or independent image correctness; existing resampling/codec tests pass.
Raw samples, compiler details, source/binary/lock/input SHA-256 are in
[the JSON report](2026-10-11-resize.json). Input preparation and provenance limitations
are described in [the archive corpus](2026-10-08-archive-corpus.json).

The synthetic benchmark excludes input copying and validation hashes from timing;
output allocation and consumed input destruction are included. Inputs are warm in
memory and alpha includes transparent/partially transparent pixels. The strong
8× thumbnail reduction is a kernel stress case; pyramid selection usually avoids
this much full-resolution work. Fractional windows exercise rational crop edges.

The real-file benchmark reuses an open local ByteSource and metadata, selects the
production TIFF pyramid/J2K reduction, then measures decode → resize → JPEG 90/4:4:4.
Header reading is reported separately as a single non-statistical observation.
JPEG buffering is included; pixel/JPEG hashes are computed after timing. Sources
and OS caches are warm. No filesystem-cache flushing, CPU affinity or frequency
control; desktop activity and thermal drift remain possible influences.

The render core excludes HTTP, Lua/permission checks, S3, result/variant caches,
watermarks, rotation and requested color conversion. It represents default-quality
local RGB/gray delivery; RGBA is covered only in the isolated kernel benchmark.
It is not a complete server latency measurement. Cache hits bypass these kernels.

## Interpretation and next step

Scaling is a worthwhile target for uncached TIFF requests, especially previews.
JP2 decode dominates this particular lossless corpus; a faster resampler alone
would have little end-to-end effect there. A 33% scaling share would limit a 2×
resampler improvement to about 20% more render-core throughput (about 16.5% less
time), assuming unchanged other stages. This is an illustrative bound, not a
measured speedup, and HTTP/auth/cache costs reduce its relevance further.

The compiler report shows a mixture: some specialized loop instances are already
vectorized, while others are rejected because of reduction dependencies,
floating-point ordering, or the cost model. It is incorrect to label the current
code entirely scalar. Do not enable fast-math globally just to suppress remarks:
rounding/alpha behavior and cross-machine repeatability need explicit validation.

Next: prototype bounded precomputation of reusable axis coordinates/overlaps for
noninteger downscaling, and inspect whether channel-specific inner loops help.
Keep the current algorithm as reference, account for scratch memory in budgets,
and verify fractional crop, RGB/gray/alpha and rounding behavior before accepting
any change. Compare isolated kernels and these same render-core workloads; only
then consider explicit portable SIMD. Repeat on actual x86 hardware before making
Intel/AMD claims. Rotation remains outside this work.

## Reproduce

Use the existing Conan Release configuration and prepared archive corpus:

```sh
cmake --build build/release --target resize-benchmark -j 6
build/release/resize-benchmark 9 \
  build/archive-images/pharch_01/pyramid.tif \
  build/archive-images/pharch_01/image.jp2 > build/resize-baseline.json
```

Pass the remaining pairs to reproduce all 36 render-core cases; the report lists
the exact input order. Repeat with reversed file arguments. With no file arguments,
only the 15 synthetic cases run. The target is excluded from normal builds and
runtime images. Source files are opened read-only; output goes to stdout.

Compiler inspection on this Mac (run separately from timing):

```sh
/usr/bin/c++ -std=c++20 -O3 -DNDEBUG -Isrc \
  -Rpass=loop-vectorize -Rpass-missed=loop-vectorize \
  -Rpass-analysis=loop-vectorize -c src/image/AreaResize.cpp \
  -o build/resize-vectorization.o 2> build/resize-vectorization.txt
```
