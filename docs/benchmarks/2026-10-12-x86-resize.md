# Scaling on the Home x86 VM — 2026-10-12

## Environment and validation

The user ran the offline AMD64 image on `media.home.org` and returned the report.
The guest exposes four vCPUs, `QEMU Virtual CPU version 2.5+`, vendor `AuthenticAMD`,
and SSE through SSE4.2, but no AVX/AVX2. These are virtual CPU descriptors, not
proof of the physical host vendor or of software CPU emulation. The user describes
an Intel host. Results characterize this VM configuration; they are not general
Intel/AMD hardware results. Container CPU quota is unlimited, memory limited to
2 GiB. GCC 13.3.0, Release; one benchmark worker.

[Unmodified raw results](2026-10-12-x86-resize.json) contain all samples and CPU
flags. Binary hashes and source manifest exactly match the prepared Docker image's
local smoke report. The four runs are before/after/after/before, each with two
warmups and nine measured iterations for all 15 synthetic cases. All 540 measured
outputs have matching fingerprints. Case sets, sample counts, medians and derived
comparisons were independently rechecked on import.

## Results

Speedup = mean of the two before medians / mean of the two after medians.

| Synthetic case | Gray | RGB | RGBA |
|---|---:|---:|---:|
| tile-half | 1.51× | 1.24× | 1.16× |
| tile-fractional | 1.64× | 1.22× | 1.22× |
| preview-noninteger | 1.52× | 1.16× | 1.17× |
| thumbnail-eighth | 1.44× | 1.09× | 1.03× |
| upscale-double | 3.34× | 2.34× | 1.98× |

RGB preview scaling falls from 30.29 to 26.01 ms (about 14% less time).
RGB enlargement falls from 22.14 to 9.47 ms (about 57% less time).
Both adjacent before/after pairs improve in every case, although magnitude varies:
gray thumbnail reduction ranges from 1.20× to 1.69× between pairs, so its aggregate
1.44× should not be treated as a precise stable estimate. RGB thumbnail reduction
is consistent at about 1.09×; RGBA's 1.03× is a small effect.

These are isolated resampling results, not end-to-end IIIF timings. No real source
images, TIFF/JP2 decoding, JPEG encoding, HTTP, authorization or cache operations
are measured. The strong thumbnail reduction is a synthetic stress case; a TIFF
pyramid usually reduces the source raster first. Do not compare absolute timings
with the native Mac baseline to rank CPU architectures: compiler, OS and VM differ.

## Decision and next step

Keep the compact axis-weight optimization: it helps this x86 VM as well as ARM64
without new dependencies or explicit SIMD. No further runtime change is needed.
The next useful measurement is the same paired run with prepared archive TIFF/JP2
files, to establish the reduction in total render-core time. Follow the
[Docker workflow](resize-docker.md#optional-real-image-render-core). Explicit SIMD
remains deferred. Changing VM CPU passthrough is not required for this comparison
and is outside this experiment.
