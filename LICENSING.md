## Third-party components and release artifacts

Third-party components retain their own licenses and notices. See
[THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md) for the inventory, embedded
components and image notice locations. License metadata alone is not a complete
notice or corresponding-source distribution.

Before publishing binary images, retain and provide access to the exact
corresponding source, including required dependency sources, patches and build
recipes, with a clear association to the published image digest. A GitHub archive
of SIPI-2 alone does not include its Conan dependency sources. The collected
inventory records source archive URLs/checksums but does not itself supply or
verify a complete corresponding-source release. This remains a publication gate.

Use `make source-package` for the library sources/recipes/notices and the committed
project. The [source package guide](docs/source-package.md) describes restoration
and binding to verified image inventories. Creating a local package does not
fulfill the separate requirement to make the final corresponding source available.
